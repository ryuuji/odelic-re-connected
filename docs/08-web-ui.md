# 08. 設定ページとスマートフォン UI（`odelic-web`）

ルーターの設定画面のように、ブラウザから設定・操作・状態確認ができるようにする。
実装は [`web/`](../web)。

✅ **実装完了（2026-07-26）。** 設計時から変えた点は [W10](#w10-設計から変えたところ) にまとめてある。

| | |
| --- | --- |
| 実装 | Node.js（`odelic-matter` と同じ）+ 素の HTML/CSS/JS（ビルド不要） |
| 配置 | ⭐ 別プロセス（`odelic-web`） |
| 公開 | LAN・HTTPS（自己署名）+ パスワード |
| 照明操作 | ⭐ `odelicd` に直接 |
| 器具名・Matter 状態 | ⭐ ブリッジの管理 API 経由（所有者を 1 つに保つ） |

---

## W1. 全体構成

```
┌──────────────────── Raspberry Pi 3 ────────────────────┐
│                                                        │
│  odelicd.py (root)          odelic-web (Node)          │
│  ├ BLE GATT (hci0)   ◀──────┤ HTTPS :8443             │
│  └ HTTP :8080        ◀──┐   │  ├ 静的ファイル（UI）    │
│                         │   │  ├ 照明操作 → odelicd    │
│  odelic-matter (Node)   │   │  ├ 設定 → 管理 API      │
│  ├ Matter ServerNode    │   │  ├ HOMEID → 特権ヘルパ  │
│  ├ 管理 API :8081 ◀─────┼───┤  └ ログ → journald      │
│  │  (localhost 限定)    │   │                          │
│  └ odelicd クライアント ─┘   └ 認証（パスワード）       │
└────────────────────────────────────────────────────────┘
```

### なぜ別プロセスか

- ⚠️ `odelicd` は BLE の安定性を実測で詰めた資産（C33）。**触らない**
- ⚠️ ブリッジは Matter の状態機械を持つ。Web 配信の都合で再起動したくない
  （commissioning 直後の再起動が危険なことは M6-6 で判明済み）
- ⭐ Web だけを再起動できる。UI の試行が他に波及しない

### ⚠️ ロジックの共有

「照明操作は `odelicd` 直接」なので、Web も **段の構成** を知る必要がある。
二重に持つと必ずずれるので、**共有する範囲を最小に切る**。

| | 置き場 | 理由 |
| --- | --- | --- |
| 製品コード → 能力（常夜灯・調色の有無） | ⭐ 共有 `common/` | 表を二重に持つと確実にずれる |
| 段の構成（常夜灯 3 段 + 主灯 20 段） | ⭐ 共有 | プロトコル由来の事実（C15-9 / C24） |
| Matter の量子化（level 1〜254 / mired） | ブリッジのみ | Web は `/night?level=` と `/level?bright=` を直接呼ぶので不要 |
| 器具名・名簿・Matter 状態 | ブリッジのみ（管理 API で読み書き） | 2 プロセスが書くと競合する |

## W2. HTTPS（自己署名）

⚠️ **自己署名はスマホのブラウザが警告を出す。** 毎回警告を踏むのは現実的でないので、
ローカル CA を 1 つ作り、それを端末に一度だけ信頼させる方式にする。

```
ローカル CA（Pi 上で生成・秘密鍵は Pi に置く）
  └ サーバ証明書（SAN: odelic-re-connected.local / <LAN IP> / localhost）
```

| 手順 | |
| --- | --- |
| 1 | Pi で CA とサーバ証明書を生成（`web/gencert.sh`） |
| 2 | CA 証明書を `https://<Pi>/ca.crt` で配布（警告を踏んで 1 回だけ取得） |
| 3 | スマホに CA をインストールして信頼 |

⚠️ **iOS は「プロファイルをインストール」に加えて
「設定 → 一般 → 情報 → 証明書信頼設定」で明示的に信頼を有効にする必要がある。**
ここを忘れると入れたのに警告が出続ける。

⚠️ **SAN に IP アドレスを入れる。** ブラウザは CN を見ないので、IP でアクセスするなら
`IP:172.16.0.16` が SAN に必要。DHCP で IP が変わると証明書を作り直すことになるため、
Pi は DHCP 固定割当か静的 IP にしておくのが望ましい。

### 参考: Tailscale なら警告なしにできた

**[事実]** `sudo tailscale cert odelic-re-connected.turtle-eagle.ts.net` で
**Let's Encrypt の正規証明書** が発行できることを確認した
（`issuer=Let's Encrypt CN=YE1` / 有効期限 3 か月 / 自動更新可）。

⚠️ ただしこの名前は Tailscale 経由でしか解決できない ので、全端末に Tailscale が必要。
今回は LAN で完結させる選択をしたので使わないが、
警告を消したくなったらこちらに切り替えられる（実装は両対応にしておく）。

## W3. 認証

⚠️ このページはメッシュのパスワード変更と Matter のフェアリング破棄ができる。
無認証にはできない。

| | |
| --- | --- |
| 方式 | パスワード 1 つ（家庭内なので単一ユーザー） |
| 保存 | `scrypt` でハッシュ化して設定ファイルに（平文で置かない） |
| セッション | HttpOnly + Secure クッキー（ランダム 32 バイト・有効期限あり）。⭐ `SHA-256` だけを永続化（→ [W11-7](#-7-セッションを永続化した生のトークンは置かない)） |
| 初期設定 | 未設定なら初回アクセス時にパスワード設定を強制する |
| 総当たり対策 | 失敗回数で遅延（IP ごと） |

⚠️ **HTTPS が前提。** HTTP ではパスワードが平文で流れるので、
HTTP で来たら HTTPS へリダイレクトする。

## W4. 画面

### 照明（スマホ向け・既定画面）

- 器具ごとのカード: 名前 / オンライン状態 / ON・OFF / 明るさ / 色温度
- ⭐ 明るさは **1 本のスライダー**（`0` が消灯、下端が常夜灯 3 段、その上が主灯 20 段）。
  Google Home と同じ考え方（→ [07 M3](07-matter.md)）
- 「すべて」カード（`target=all` の 1 通で送る）
- ⚠️ 常夜灯に対応しない器具ではスライダーの下端を主灯 5〜15% にする（能力で分岐）。
  ⭐ 一斉操作では「全器具が常夜灯対応のときだけ」常夜灯の段を出す
  （1 台でも非対応なら `/night` を投げてはいけない）
- ⚠️ オフラインの器具は操作を無効化し、状態を「不明」と出す（P4: 嘘をつかない）
- ⚠️⚠️ 明るさの中間値を連射しない。`input` ではラベルだけ更新し、
  送信は `change`（指を離したとき）＋ 200 ms デバウンス。
  公式アプリは約 143 ms 間隔で 16 通送っていた（→ [02 C28](02-protocol.md)）
- ⚠️ 消灯中は色温度スライダーを無効にする（`/level` は点灯させてしまうため）

### 状態

- 器具ごと: MAC / 製品 / グループ / ファーム / vAddr / 最終更新
- `odelicd` の `/metrics`: RTT 分布・到達率・リンク寿命・切断理由
- Matter: commissioning 状態 / fabric / エンドポイント

### 設定

- **メッシュ ID（8 桁）** の入力・変更 → W5
- 器具の名前（ブリッジの管理 API 経由）
- 色温度のケルビン範囲・`nightBandPercent`・`statusRefreshSec` など

### Matter の登録

- QR コードと手入力コードの表示（未 commissioning のとき）
- ⭐ **追加フェアリング**（multi-admin）で Apple Home / Alexa を追加
- ⚠️ **フェアリングの破棄**（ストレージ消去）は破壊的。二段確認にする

### ログ

- `journalctl -u odelicd -u odelic-matter -u odelic-web` の直近を表示
- ⚠️ ログには HOMEID / パスワードが出る箇所がある（`鍵を導出:` の行など）。
  **表示前にマスクする**

## W5. HOMEID の設定（特権操作）

⚠️ `odelic-web` は非 root で動かす。しかし ID の保存先
`/etc/default/odelicd`（0600 root）への書き込みと `odelicd` の再起動には root が必要。

→ ⭐ **専用ヘルパ 1 本だけを sudoers で許可する。**

```
# /etc/sudoers.d/odelic-web
odelic-web ALL=(root) NOPASSWD: /opt/odelic-web/set-id.sh
```

`set-id.sh` は次だけを行う（引数を厳密に検証し、それ以外は何もしない）。

1. 8 桁の数字であることを確認（それ以外は拒否）
2. `/etc/default/odelicd` の `ODELIC_ID` を書き換え（0600 を維持）
3. `systemctl restart odelicd`

⚠️ `--install` 系のような汎用スクリプトを sudoers に入れてはいけない。
引数で任意のことができると、Web の脆弱性が即 root になる。

### 入力ミスの検出

⭐ **誤った ID は器具の応答で即座に分かる**（→ [02 C23-1](02-protocol.md)）。
`PERIPHERAL_LOGIN` を LOGINKEY で復号し、先頭 4 バイトが HOMEID と一致するかを見る。

→ 保存後に `GET /info` を数十秒監視し、`joined` にならなければ
「ID が違う可能性があります」と出して **元の ID に戻せる** ようにする。

### スコープ外

⚠️ HOMEID の新規発行・変更（器具の再登録）は行わない。
破壊的で、壁スイッチからのやり直しになる（→ README の「意図的に対応しないこと」）。
このページで行うのは **既存の 8 桁 ID を教えること** だけ。

## W6. ブリッジに追加する管理 API

⚠️ **localhost 限定**（`127.0.0.1:8081`）。認証は `odelic-web` 側で済ませる。

| メソッド | パス | 内容 |
| --- | --- | --- |
| `GET` | `/admin/state` | 器具（名前・能力・到達状態）+ Matter の状態 |
| `GET` | `/admin/config` | 公開してよい設定（ケルビン範囲・`nightBandPercent` など） |
| `POST` | `/admin/config` | 上を更新。⭐ 再起動が要る項目名を応答で返す |
| `GET` | `/admin/commissioning` | QR / 手入力コード / commissioned / fabric |
| `POST` | `/admin/commissioning/open` | 追加フェアリングの窓を開く（multi-admin） |
| `POST` | `/admin/fixtures/<mac>/name` | 器具名の変更（名簿に保存・⭐ 再起動不要） |
| `DELETE` | `/admin/fixtures/<mac>` | 名簿から外す（⚠️ 破壊的） |
| `POST` | `/admin/restart` | ⭐ 自分できれいに終わる（systemd が上げ直す） |
| `POST` | `/admin/factory-reset` | ⚠️⚠️ フェアリングの破棄（合言葉が要る） |

⚠️ 器具名の変更は **Google Home 側の名前を上書きしない**（→ [07 M6](07-matter.md)）。
UI にその旨を明記する。

⚠️⚠️ `host` が `127.0.0.1` 以外だと起動時にエラーで止まる。
無認証なので、LAN に開くと誰でも器具名の変更とフェアリングの破棄ができてしまう。
黙って直さず止めて気づかせる。

## W10. 設計から変えたところ

実装しながら変えた判断。理由つきで残す。

### ⭐ 1. HTTP のリダイレクトはポートを増やさずにやった

「HTTP で来たら HTTPS へリダイレクト」を、**同じ 8443 で受けて先頭 1 バイトを覗く**
方式にした（`0x16` = TLS handshake なら HTTPS、それ以外は 301）。

- `odelicd` が 8080、ブリッジの管理 API が 8081 を使っている
- 80 / 443 は `CAP_NET_BIND_SERVICE` が要る（権限を増やしたくない）
- ⚠️ スマホで `host:8443` と打つとブラウザは `http://` を既定にする。
  判別しないと「安全に接続できません」としか出ず、原因が分からない

### ⭐ 2. 段の計算はサーバ側で完結させた（`/vendor/common` は作らなかった）

当初は `@odelic/common` の `dist` をブラウザへ配って段を計算させる案だった。
やめて、サーバが **段のラベルの配列と現在の添字** を返し、
ブラウザは「何段目にしたか」を送り返すだけにした。

- ブラウザに段の定義を持たせないので、`common` を作った目的（二重に持たない）は同じく達成できる
- ESM の解決（`import.meta.resolve`）も CSP の調整も要らなくなった
- 段 → コマンド（`/night` か `/level` か）の判断も 1 か所に寄る

### ⭐ 3. 器具名と設定の保存先を `config.json` から外した

`config.json` は **コメント付きで配っている**（`config.example.json` が雛形）。
プログラムから書き戻すと **コメントが全部消える**。

→ 設定ページからの変更は `/var/lib/odelic-matter/` に置く。

| 何 | どこ | 優先順位 |
| --- | --- | --- |
| 器具の表示名 | `fixtures.json` の `displayName` | ⭐ これ > `config.json` の `name` > 既定名 |
| ケルビン範囲など | `settings.json` | ⭐ これが `config.json` に重なる |

⚠️ 一度設定ページで名前を付けると `config.json` の `name` は効かなくなる。
起動時のログにどちらを使ったかを出している。

### ⭐ 4. ホーム ID はそのまま画面に出す（一度伏せてから戻した）

当初は下位 4 桁（メッシュのパスワード）を `1234••••` と伏せていた。**やめた。**

- 同じ 8 桁が **公式アプリのメニュー画面に平文で出ている**。ここだけ伏せても守れるものが無い
- 設定し直すときに現在値が読めないほうが困る（本人が見る画面なのに）
- 画面はログイン済み + HTTPS の内側。ログとは前提が違う

→ `set-id.sh --status` は `id=12345678 rollback=yes` を返し、設定画面はそのまま表示する。

⚠️ ログのマスク（`src/mask.ts`）は外さない。 ログは第三者に見せることがある。
⭐ 巻き戻しはヘルパ側の退避ファイルで行うので、Web が旧値を覚える必要はない。

### 5. QR は matter.js のものをそのまま使う

`@matter/types` の `QrCode.get()` が **文字ブロックの QR** を返すので、
`<pre>` に流し込むだけにした。QR エンコーダのライブラリを足していない。
⚠️ 暗いテーマだと読めないので、QR だけ白地・黒文字に固定している。

### 6. ⚠️ 再起動は「自分できれいに終わる」で実現した

設定ページの「ブリッジを再起動」は、`systemctl` を sudo で叩くのではなく
ブリッジ自身が `SIGTERM` 相当の終了処理をして落ちる（`Restart=always` が上げ直す）。
sudoers に増やすものを `set-id.sh` 1 本のままにできる。

⚠️⚠️ commissioning 直後は 409 で断る（Nest ハブが配下の器具を失う・[07 M6-6](07-matter.md)）。

## W11. 表現とデザインの方針（2026-07-26 に決めた）

一通り動いたあとで、見た目と日本語を通しで見直した。決めたことを残す。

### ⭐ 1. アクセントは琥珀。favicon と揃える

当初は汎用の青（`#0a6cff`）だったが、favicon は琥珀（`#f2b705`）で **ブランドがずれていた**。
扱っているのが照明なので、琥珀に寄せた。

⚠️ 琥珀は明度が高く **白文字が乗らない。** 用途で 3 つに分けてある。

| 変数 | 用途 |
| --- | --- |
| `--accent` | 塗り（primary ボタン・選択中のタブ・点灯ランプ） |
| `--accent-fg` | ⚠️ `--accent` の上に置く文字。暗い色 |
| `--accent-ink` | 文字・境界に使う濃い琥珀（地の上でも読める） |

### ⭐⭐ 2. 明るさスライダーのトラックそのものを明るさの帯にした

「下端が常夜灯、その上が主灯」という軸の作り（[07 M3](07-matter.md)）は、
言葉で説明するより **色で見せたほうが早い**。

```
消灯（灰）│ 常夜灯（暗い橙 → 橙）│ 主灯（琥珀 → 温白）
```

- 境目は JS が `--off-stop` / `--night-stop` で渡す。
  段の定義はブラウザに持たせない（サーバから来た `rungs[].kind` を数えるだけ）
- ⭐ 境目は「段と段の中間」に置く。つまみは `0〜max` の `max+1` か所に止まるので
  `(i + 0.5) / max` がちょうど間になる
- ⚠️ **トラックの高さをつまみと同じ 32px にしてある。** こうすると
  「トラックを input の中で縦中央に置く」というブラウザ差の大きい調整が丸ごと要らなくなる
- 色温度スライダーも同じ形（電球色 → 昼光色のグラデーション）

⭐ 「明るさの帯」の色は テーマで変えない。光そのものの色なので、
暗いテーマでも同じでよい（変えるのは消灯部分の灰色だけ）。

### ⭐ 3. 画面の日本語から `⚠️` `⭐` を外した

**コードコメントの流儀を UI に持ち込んでいた。** 画面のあちこちに ⚠️ が出ると、
どれが本当に危ないのか区別が付かなくなる。

→ `notice(kind, title, body)` に統一し、**見出しの色**（何が起きているか）と
面の色（どれくらい困るか）で強さを示す。

⚠️ 左端に色帯（`border-left: 3px solid …`）を差すのもやめた。意味を持たないのに視線を奪う。
⭐ コードコメント側の `⚠️` / `⭐` は今の流儀のまま残す（読み手が違う）。

### ⭐ 4. 電源はセグメントにした（ボタンであり表示でもある）

「点ける / 消す」を並べただけだと **今どちらなのかが分からない**。
`aria-pressed` で現在の状態を示すセグメントにして、状態表示を兼ねさせた。

⚠️ 「すべての照明」カードは **全部点いている / 全部消えている ときだけ** 断定する。
混在しているときはどちらも押されていない状態にする（P4: 嘘をつかない）。

### 5. ヘッダーとタブを 1 つの `sticky` にまとめた

`nav { top: 53px }` がヘッダーの実高さのハードコードになっていて、
文字サイズが変わるだけで隙間や被りが出る作りだった。

⚠️ ノッチの余白（`env(safe-area-inset-top)`）は `body` ではなく **`.topbar` に付ける**。
`body` に付けると sticky が画面上端ではなく余白の下で止まる。

### 6. 名乗りを統一した

画面の名前は **ODELIC Re-Connected ウェブ管理画面**。
⭐ 家族も使うので、`照明` タブとログイン画面からは内部用語を外した
（`odelicd 停止` → `操作不可` / `照明サーバ（odelicd）に届いていません`）。
⚠️ `状態` `Matter` `ログ` の 3 タブは **技術用語のまま残す**。調べるときに要る。

### ⭐ 7. セッションを永続化した（生のトークンは置かない）

当初はメモリ内のみで、`systemctl restart odelic-web` のたびに全員ログアウトしていた。
**実用に耐えなかった** ので `/var/lib/odelic-web/sessions.json`（0600）に置くことにした。

⚠️⚠️ 生のトークンは書かない。書いたらそのファイルは Cookie そのものになる。
⭐ 保存するのは **`SHA-256(token)`** だけ。照合は受け取ったトークンを SHA-256 して引く。

⚠️ パスワードと違って遅いハッシュは要らない（トークンは 32 バイトの乱数）。
⚠️⚠️ 各セッションは発行時のパスワードの `updatedAt` を持つ。
`reset-password.sh`（= `install.sh --show-password`）は `auth.json` をプロセス外で差し替えるので、
これが無いとリセット後も古いセッションで入れてしまう。

### ⭐ 8. パスワードを見失ったときの出口をログイン画面に置いた

⚠️ **ブラウザから再設定させる導線は作らない**（W3 のとおり、LAN 内で先に到達した人が
決められてしまう）。代わりに **Pi で打つコマンドをログイン画面に載せる**。

```
sudo journalctl -u odelic-web | grep 初期パスワード     # 生成時のログが残っていれば
sudo /opt/odelic-web/reset-password.sh                # 作り直す（⚠️ 全端末ログアウト）
```

⭐ `.cmd` は `user-select: all` にしてある（スマホでタップすると全選択できる）。

⚠️⚠️ 最初は `sudo /opt/odelic-web/install.sh --show-password` と案内して間違えた。
`install.sh` は `/opt` に配られない（配られるのは `src` / `dist` / `public` /
`package.json` / `set-id.sh` だけ）ので `command not found` になる。

⭐ `install.sh` を `/opt` に置いて済ませてはいけない。`install.sh` は
`$(dirname $0)` を ソースツリー とみなすので、`/opt` から実行すると
`cp -r "$SRC/src" "$DEST/src"`（自分自身を自分にコピー）になって壊れる。

→ 専用の入口 `reset-password.sh` を作って `/opt/odelic-web/` に置いた。
`install.sh` はこれを source して同じ関数を使う（実装を 2 か所に持たない）。
⚠️ こちらは sudoers に入れない（人が `sudo` で叩くもの。sudoers は `set-id.sh` だけ）。

## W12. ⭐ API の公開範囲を選べるようにした（2026-07-26）

`odelicd` の HTTP API（既定 8080）は **認証を持たない。**`POST /on` に鍵は要らない。
それを LAN に出すかどうかを設定画面で切り替えられるようにした。

| | |
| --- | --- |
| ⭐ 既定 | `127.0.0.1`（localhost 限定） |
| LAN に出す | 設定画面で明示的に選んだときだけ（確認ダイアログを挟む） |
| ヘルパ | `set-api.sh`（sudoers で許可する 3 本のうち 1 本） |
| 受け付ける引数 | `--status` / `local` / `lan` の 3 つだけ（任意のアドレスは渡せない） |

### ⭐ localhost 限定でも機能は落ちない

これが設計の要点。Matter ブリッジも設定ページも `127.0.0.1` から `odelicd` を叩く。

- 🎙 音声操作（Google Home / Apple Home / Alexa）→ ブリッジ経由なので影響なし
- 📱 スマートフォンからの操作 → 設定ページ（8443）経由なので影響なし

→ LAN に出す価値があるのは「別のマシンのスクリプトから直接叩きたい」ときだけ。
だから既定を閉じても失うものがほぼ無い。

### ⚠️⚠️ 既定を変えたときの移行の罠

`--bind` の既定を `0.0.0.0` から `127.0.0.1` に変えた。⚠️ 3 か所で安全側に倒している。

1. `odelicd.service` の `--bind ${ODELIC_BIND}` — 古い `/etc/default/odelicd`
   には `ODELIC_BIND` が無い。systemd は未設定の `${VAR}` を **空の引数** に展開するので、
   そのまま渡すと Python が `""` を「全インターフェース」と解釈して **逆に全公開になる**。
   → ⭐ `odelicd.py` が 空文字を `127.0.0.1` に倒す。
2. `odelicd/install.sh` — 既に `ODELIC_BIND` があればその値を尊重する。
   入れ直しただけで開いたり閉じたりしたら驚く。
3. 起動ログ — LAN に出ているときは
   `⚠️⚠️ LAN に公開しています。この API に認証はありません` を必ず出す。

⚠️ **既に LAN 経由で `curl http://odelic-re-connected:8080/on` を使っていた場合、
更新すると止まる。** 設定画面で「LAN に公開する」を選び直すこと。

### ⚠️ 「読み取れない」を「localhost」と表示しない

`--status` の出力が解釈できなかったときは `null` を返し、画面には
**「今の設定を読み取れませんでした」** と出す。⭐ 安全側の既定を表示すると
**実は開いているのに閉じて見える**。それが最悪。

## W13. ⭐ バックアップと復元（2026-07-26）

設定画面から ZIP で落とせて、その ZIP から戻せるようにした。

| | |
| --- | --- |
| ヘルパ | `backup-helper.py`（sudoers で許可する 3 本のうち 1 本） |
| 受け付ける引数 | `--targets` / `--info` / `--export` / `--restore` |
| ダウンロード | POST `/api/backup/export` → `application/zip` + `Cache-Control: no-store` |
| 復元 | POST `/api/backup/restore`（ボディがそのまま ZIP） |
| 対象 | `backup-helper.py` の `TARGETS`（⭐ ここが唯一の正。`--targets` で読める） |

### ⚠️⚠️ この ZIP は Pi ごと持ち出せる鍵束

メッシュのパスワード・Matter の fabric 秘密鍵・**ローカル CA の秘密鍵**・
設定ページのパスワードのハッシュが入る。⭐ **画面にそう書く。**
「バックアップ」という言葉だけでは、渡してはいけないものだと伝わらない。

- ⭐ 一時ファイルに落とさない。 ヘルパの標準出力／標準入力で流す
  （`odelic-web` が読める場所に平文を置かない）
- ⭐ ダウンロードは GET にしない。 他サイトのリンクや `<img>` で不意に
  始まり得るし、このプロジェクトは GET を CSRF 検査の対象外にしている
- ⚠️ `Cache-Control: no-store`（プロキシやディスクに残さない）

### ⚠️ なぜヘルパが Python なのか

`--restore` は **他人が作った ZIP を root で展開する。** このリポジトリで
いちばん危ない処理で、シェルでは書き切れない。

- エントリ名は `files/<TARGETS のどれか>/…` **だけ** を通す
  （`..` / 絶対パス / `\` 区切り / 「対象名 + 接尾辞」の別ディレクトリを弾く）
- 展開の前に全エントリを検証する（半分だけ復元された状態を作らない）
- シンボリックリンク・デバイスを root で作らせない
- ⭐ `python3` は `odelicd` が必須にしているので依存は増えていない

### ⭐ 所有者は manifest で運ぶ

ZIP は所有者を保持しない。⚠️ 復元後に `root:root` のまま起動すると、非 root の
サービスが自分の状態ファイルを読めず「起動はするのに動かない」になる
（`reset-password.sh` に同じ罠の記録がある）。

→ `manifest.json` に **ユーザー名・グループ名・パーミッション** を書いて運び、
復元時に名前から解決して付け直す。⚠️ uid ではなく **名前** で持つ
（入れ直した Pi では uid が変わる）。

### ⚠️ 踏んだ罠: `writestr` は種別ビットを書かない

`zipfile.writestr` が `external_attr` に入れるのは `0o600 << 16`（**ファイル種別
ビットなし**）。復元側を `stat.S_ISREG()` で検査していたため、
自分で作ったバックアップまで「通常ファイルでない」と拒否していた。

→ ⭐ 種別ビットが「立っていて、かつ通常ファイルでない」ものだけを弾く
（`S_IFMT(mode) not in (0, S_IFREG)`）。あわせて `--export` 側も
`S_IFREG | mode` を書くようにした（`unzip` から見ても型が分かる）。
