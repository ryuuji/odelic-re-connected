# 解析の記録

ここは **成果物ではなく、成果物がどう作られたかの記録**。
プロトコルを自分で確かめ直したい人、別のプラットフォームに移植したい人、
同じ製品を解析する人のために残している。

⭐ プロトコルの確定事項を引くなら [../02-protocol.md](../02-protocol.md)。
ここにあるのは、そこに至るまでの手順・失敗・打ち切った検討。

## 番号について

⚠️ `01` `03` `04` `05` `09` と歯抜けになっているのは意図的。
解析当時の通し番号をそのまま維持している。文書の本文には
`[02 C33]` `[03 I7]` `[07 M9]` という形の相互参照が 24 か所あり、
番号を振り直すと文章のほうが壊れる。

成果物側の文書（`../02-protocol.md` `../06` `../07` `../08` `../10`）と
番号空間を共有しているので、`02` と `06`〜`08` はここには無い。

## ⚠️ このリポジトリに含まれないもの

| もの | 理由 |
| --- | --- |
| 解析対象の APK | 配布不可 |
| 逆コンパイル成果物（jadx の出力） | 同上。APK から再生成できる |
| `libnative-lib.so` | 同上 |
| HCI スヌープログ（`*.btsnoop` / `*.log`） | 端末固有情報を含む |
| 器具ファームウェア（APK 同梱の OTA イメージ） | 配布不可 |

作業用の置き場は `artifacts/`（Git 管理外）。
[04-analysis-procedure.md](04-analysis-procedure.md) に取得手順がある。

⚠️ 8 桁 ID の実値もリポジトリには入っていない。
文書中の `12345678`（HOMEID `1234` / パスワード `5678`）は **すべてプレースホルダ**。
下位 4 桁はメッシュのパスワードで、知られると近隣の誰でも照明を操作できる。

## 法的な位置づけ

自身が所有する照明器具を相互運用（interoperability）するための解析。
プロトコル知識をもとに独自実装を行うもので、**公式アプリのコードやアセットを
再配布しない**。→ 実装が案 D（完全自前実装）に落ち着いた経緯は
[05-app-design.md](05-app-design.md) の冒頭。
